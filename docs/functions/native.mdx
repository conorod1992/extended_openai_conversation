Native functions are capabilities implemented directly by Extended OpenAI Conversation. In the Tools page, choose **Add Function Tool**, then **Insert Built-in Function** to insert an editable preset into the YAML editor.

## Available Native Functions

### execute_service

Call one or more Home Assistant services on Assist-exposed targets.

The native runtime accepts normal Home Assistant service-specific data, not only target fields. For example, `light.turn_on` can receive `brightness_pct`, `color_name`, `color_temp_kelvin`, `rgb_color`, `transition`, and other fields supported by that Home Assistant service.

<ParamField path="list" type="array" required>
  One or more service calls. Each item contains `domain`, `service`, and `service_data`.
</ParamField>

<ParamField path="list[].domain" type="string" required>
  Home Assistant service domain, for example `light`, `switch`, `climate`, or `media_player`.
</ParamField>

<ParamField path="list[].service" type="string" required>
  Service name, for example `turn_on`, `turn_off`, or `set_temperature`.
</ParamField>

<ParamField path="list[].service_data" type="object" required>
  Any valid data accepted by the selected Home Assistant service. Include at least one exposed target using `entity_id`, `device_id`, `area_id`, `floor_id`, or `label_id`. Service-specific fields are allowed alongside the target.
</ParamField>

<Info>
The built-in service-call presets intentionally use `strict: false` because `service_data` is an open Home Assistant mapping whose valid keys depend on the selected service. Target exposure and Home Assistant permission checks are still enforced by the backend.
</Info>

<Accordion title="Example Configuration">

```yaml
- spec:
    name: execute_service
    description: Execute one or more Home Assistant services on exposed targets.
    strict: false
    parameters:
      type: object
      properties:
        list:
          type: array
          items:
            type: object
            properties:
              domain:
                type: string
              service:
                type: string
              service_data:
                type: object
                description: >-
                  Any valid Home Assistant service data. Include an exposed target;
                  service-specific fields such as brightness_pct or color_temp_kelvin
                  are also allowed.
                additionalProperties: true
            required:
              - domain
              - service
              - service_data
      required:
        - list
  function:
    type: native
    name: execute_service
```

For example, the model may call `light.turn_on` with:

```yaml
service_data:
  entity_id:
    - light.study
  color_temp_kelvin: 2700
  brightness_pct: 60
```

</Accordion>

### execute_service_single

Call exactly one Home Assistant service. It has the same open `service_data` contract and the same exposure/permission enforcement as `execute_service`, but `domain`, `service`, and `service_data` are top-level arguments rather than entries in a `list`.

<ParamField path="domain" type="string" required>
  Home Assistant service domain.
</ParamField>

<ParamField path="service" type="string" required>
  Home Assistant service name.
</ParamField>

<ParamField path="service_data" type="object" required>
  Any valid data accepted by the selected service, including an exposed target and service-specific fields.
</ParamField>

### send_broadcast

Send a spoken Broadcast announcement to an announcement-capable Assist Satellite. Busy satellites are queued rather than interrupted.

<ParamField path="message" type="string" required>
  Exact message to announce.
</ParamField>

<ParamField path="destination" type="string">
  Natural Home Assistant area, device, floor, label, or Assist Satellite name. Required unless `whole_home` is `true`.
</ParamField>

<ParamField path="whole_home" type="boolean">
  Send to every announcement-capable Assist Satellite except the originating satellite. When false or omitted, `destination` is required.
</ParamField>

### add_automation

Create a Home Assistant automation from a complete YAML configuration.

<Warning>
Before using this function, set up notifications for the `automation_registered_via_extended_openai_conversation_responses` event. Automations can be created even if the conversation later fails to produce a response.
</Warning>

<ParamField path="automation_config" type="string" required>
  One complete Home Assistant automation in valid YAML. The integration validates it before writing and reloads automations after the atomic update.
</ParamField>

<Accordion title="Example Configuration">

```yaml
- spec:
    name: add_automation
    description: Create a Home Assistant automation from a complete YAML configuration.
    parameters:
      type: object
      properties:
        automation_config:
          type: string
          description: A complete Home Assistant automation in valid YAML.
      required:
        - automation_config
  function:
    type: native
    name: add_automation
```

</Accordion>

### get_history

Retrieve historical state data for Assist-exposed Home Assistant entities.

<ParamField path="entity_ids" type="array" required>
  Entity IDs to retrieve history for.
</ParamField>

<ParamField path="start_time" type="string">
  ISO 8601 start time. Defaults to one day before the request time.
</ParamField>

<ParamField path="end_time" type="string">
  ISO 8601 end time. Defaults to one day after the resolved `start_time`.
</ParamField>

<ParamField path="include_start_time_state" type="boolean">
  Include the state immediately before the requested start time. Default: `true`.
</ParamField>

<ParamField path="significant_changes_only" type="boolean">
  Return only significant state changes. Default: `true`.
</ParamField>

<ParamField path="minimal_response" type="boolean">
  Use Home Assistant's minimal history representation. Default: `true`.
</ParamField>

<ParamField path="no_attributes" type="boolean">
  Omit state attributes. Default: `true`.
</ParamField>

### get_energy

Retrieve Home Assistant Energy dashboard configuration and preferences.

<Info>
This function has no model arguments. If the Energy configuration references Home Assistant entities that are not exposed to Assist, the native runtime refuses to disclose the configuration.
</Info>

### get_statistics

Retrieve Home Assistant long-term statistics for a time period.

<ParamField path="statistic_ids" type="array" required>
  One or more statistic IDs. Entity-backed IDs must be exposed to Assist; valid external integration statistic IDs are also supported. Maximum: 100.
</ParamField>

<ParamField path="start_time" type="string" required>
  ISO 8601 start time.
</ParamField>

<ParamField path="end_time" type="string" required>
  ISO 8601 end time.
</ParamField>

<ParamField path="period" type="string">
  Aggregation period: `5minute`, `hour`, `day`, `week`, `month`, or `year`. Default: `day`.
</ParamField>

<ParamField path="units" type="object">
  Optional unit conversions keyed by Home Assistant unit class, for example `power`, `energy`, or `temperature`, with Home Assistant unit strings as values.
</ParamField>

<ParamField path="types" type="array">
  Values to return. Supported values are `change`, `last_reset`, `max`, `mean`, `min`, `state`, and `sum`. Default: `["change"]`.
</ParamField>

<Info>
The statistics preset uses `strict: false` because `units` is an open mapping keyed by Home Assistant unit class. The preset still constrains `period` and each `types` item to values supported by Home Assistant's recorder API.
</Info>

<Accordion title="Example Configuration">

```yaml
- spec:
    name: get_statistics
    description: Retrieve Home Assistant long-term statistics for a time period.
    strict: false
    parameters:
      type: object
      properties:
        statistic_ids:
          type: array
          items:
            type: string
          minItems: 1
          maxItems: 100
        start_time:
          type: string
        end_time:
          type: string
        period:
          type: string
          enum:
            - 5minute
            - hour
            - day
            - week
            - month
            - year
        units:
          type: object
          additionalProperties:
            type: string
        types:
          type: array
          items:
            type: string
            enum:
              - change
              - last_reset
              - max
              - mean
              - min
              - state
              - sum
      required:
        - statistic_ids
        - start_time
        - end_time
  function:
    type: native
    name: get_statistics
```

</Accordion>

### get_user_from_user_id

Return the current Home Assistant user's display name from the conversation context.

<Info>
This function takes no model arguments. Despite the historical function name, the model does not supply a user ID; the native runtime uses the authenticated Home Assistant conversation context.
</Info>
